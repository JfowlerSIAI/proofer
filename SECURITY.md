# Security policy

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/JfowlerSIAI/proofer/security/advisories/new).
If that channel is unavailable, email [the maintainer](docs/privacy-policy.md#contact)
with the subject **Proofer security report**. Report security concerns privately
before opening a public issue or pull request.

Include the affected Proofer version or commit, browser and operating system,
the impact you observed, and minimal reproduction steps using synthetic text.
Examples include unauthorized access to typed text, corrections made after
consent was withdrawn, or a page reaching privileged extension operations.

Do not send credentials, access tokens, exported proofreading logs, private
documents, or other people's writing. If the issue depends on sensitive data,
describe that dependency so we can agree on a safe reproduction. Review setup
reports and screenshots before sharing them, even in a private report.

## Support and disclosure

Security fixes are developed against the current default branch. Older
releases do not have a separate maintenance guarantee; please identify your
version and whether the problem also occurs on the current code.

This is a small project with best-effort security support and no guaranteed
response time or bug bounty. The maintainer will work with reporters to
understand reproducible issues and coordinate a fix and disclosure. A public
report should use sanitized reproduction steps and omit user data.

Ordinary bugs can be reported through the issue tracker. See
[CONTRIBUTING.md](CONTRIBUTING.md) for what to include and the
[privacy policy](docs/privacy-policy.md) for how Proofer handles writing
and local records.
